# 简单申请查询、缓存与 NAT/有效期联动

本轮在已有不可变防火墙图、策略算法、快照及设计证明上补齐业务入口。
修改位于 `refactor/idiomatic-go` 工作树，保留此前未提交改动；没有提交、
发布、访问设备或执行下发。

## 使用方式

```sh
go run ./cmd/firemon request-query --store ./snapshots \
  --src '192.0.2.10, 192.0.2.11' --dst 198.51.100.20 --service 443

go run ./cmd/firemon request-query --store ./snapshots \
  --src 192.0.2.10 --dst 198.51.100.20 \
  --start 2026-11-09T00:00:00Z --end 2026-11-10T00:00:00Z
```

裸端口按 TCP 解释，UDP 写成 `udp/53`。不填服务表示查询所有服务。
CLI 也接受 `--file` 批量 JSON；`version` 可省略。源目 IP、CIDR、范围和
端口列表在每一行内形成申请范围，不把不同行的源目集合相乘。

```json
{"requests":[
  {"id":"web","src":"192.0.2.10,192.0.2.11","dst":"198.51.100.20","service":"443"},
  {"id":"dns","src":"192.0.2.30","dst":"198.51.100.53","service":"udp/53"}
]}
```

服务层复用 `operations.Searcher`，也可把同一个 `inventory.Cache` 交给
Searcher 和 BatchDesigner。管理员在构造选项中配置 Topology、Clocks 和
算法预算，业务用户保留简单输入。CLI 对应 `--topology`、设计时的 `--clocks`。

## 组件及业务责任

| 组件 | 本轮实现 |
| --- | --- |
| 输入归一化 | 全角 ASCII、空白、列表分隔、引号、BOM、CIDR 网络规范化、重复/重叠范围合并；保留原始错误值 |
| `inventory.Cache` | 按不可变 revision 缓存图和索引；有界 LRU、并发加载合并、取消隔离、失败不缓存 |
| `inventory.Index` | 平衡区间树；索引接口网络、zone、非默认路由、地址对象、静态映射和动态池候选，保留原生 scope/VRF/地址视角 |
| `operations.Searcher` | 冻结一代 manifest；查询两端设备、关联静态 NAT、按时间重算，汇总匹配与未知证据 |
| `policy.Engine.Declared` | 规则几何匹配，与启停、有效期和首条命中分开；共用 Fortinet VIP 选择逻辑，保留 ASA 多 ACL 上下文 |
| `policy.Engine.OriginalTraffic` | 使用 `PacketPath.PolicyNAT` 将实际策略坐标精确还原到受限原始流量域；查询和迁移共同使用 |
| `policy.Engine.Windows` | 有限区间内按已知策略/NAT/时区边界精确切分，保留重复状态的各个实际时间段 |
| `BatchDesigner.Design` | 复用归一化和关联结果，准入明确的服务、拓扑与时钟证据；有限期申请生成原生 schedule 并执行既有安全证明 |

移除 `BatchDesigner.Query` 和用布尔开关混合查询、设计的执行路径。
高级 `Traffic`、`Targets`、`WireCandidates`、`NativeEffects` 仍各自表达实际
领域能力；没有为旧入口增加别名或兼容包装。快照格式未因这些运行期对象变化。

缓存只存不可变对象和索引，不存 manifest、策略判定或有效期状态。每次查询
都会读最新 manifest；同一查询保持一致 revision。加载直接恢复快照，不重新
解析配置，也不访问数据库。缓存默认 64 个条目、128 MiB 源文本、100 万声明
计费单位；声明计数不是 Go 堆大小估算。调用方可配置保留上限及 policy.Limits。
`Cache.Index(ctx, revision, fw)` 接收调用者已加载的不可变图，不再次读取快照。
索引仅能附加到 revision 与图指针均一致的缓存条目，不能将传入图写入来源缓存。
同一查询按 revision 持有图和索引，即使图超过保留上限或全局 LRU 淘汰条目，
也不会在该批次再次加载或构建；批次结束后这些局部引用释放。

## 业务语义与证明

- 一个错误 token 使该行整体失败，不能悄悄删去错误 IP/端口后执行剩余部分。
  不匹配的地址族也不会静默丢弃。有效兄弟行保留。预算、取消为批次级失败。
- 未填写服务可以查询所有协议。归一化后的 `ServiceSpecified` 区分真正省略
  与明确的 `any`；空白/引号/BOM 不能绕过设计准入。明确 `any` 仍须通过原生
  表达及外部行为保持证明。
- 地址、路由和 NAT 命中仅是设备关联候选，不能证明网络归属或入口。自动推断
  结果标记 `conditional`；revision 绑定的 protection 和 ingress 证据齐备后
  才能授权设计。多源/不同入口按精确流量分片，已确认部分不会被未知部分
  一并吞掉；缺路由的 ASA 命名 ACL 仍可作为条件声明展示。默认路由不能
  独自证明候选归属。
- 缺少接口资料时，已有规则的原生 scope、规则集及 zone 引用仍可形成条件声明
  查询。这不补造 packet 入口或 VRF 归属，不能生成 covered 结论或配置计划。
  zone 表为空或原生引用缺失时，同样保留声明：空上下文表示未知，实际策略
  流量保留在 `Unknown`，不声称已经有效放行。
- 高级 `Traffic` 输入显式选择 `real` 或 `translated` 时，只查询对应视角的
  原生前向验证结果；不会先把输入当作原始报文，也不继续扩展其他坐标的关联。
  无法确认映射或入口时保留该视角的未知/未匹配证据。
- 同一设备的两端、不同设备的两端都能关联。静态地址/端口变化可继续发现其他
  设备；传播受因果有效期约束，重复路径合并来源。所有发现保留计算预算。
  这些结果不宣称已经证明跨设备的物理路径。
- 静态别名先按实际 Match 收窄映射，再经过原生顺序的完整前向校验。动态池是
  可能的会话分配，不反推唯一地址/端口，不生成确定的下游绑定。
- `Declared`、`Effective`、`Original` 分别表示规则声明、实际首条命中和原始
  坐标命中，并分别保留已知性。停用、过期、未开始及被前序遮蔽的声明仍可见。
- 时间区间是 `[Start, End)`。日历使用时区转移和实际周期边界，不按分钟采样。
  修复本地 Go 1.27.1 `ZoneBounds` 在 POSIX 后备规则的闰年末尾返回非递增边界
  时的处理；查询分段和已有生命周期上下文共用该修复。
- 查询允许已发布的不完整快照，但保留诊断，并将结果强制设为 conditional。
  未知条件只影响它可能匹配的流量；顶层未知仍阻止确定结论。此类图不能进入
  配置规划，即使某一规则局部看起来确定。
- 有限期设计必须有与设备身份、源摘要、采集时间绑定的 `ScheduleClock`。
  无证据时保持 pending，不降级为无限期放行。既有整目标、目标外保持和独立
  原生回读证明继续执行，设计结果不代表设备已下发。

## 验证与性能

主模块的 `go test ./...`、`go test -race ./...`、`go vet ./...`、
`go build ./...`、staticcheck 及受改动主要 Go 文件的 gopls 检查均通过。
日历、缓存、NAT、设计和 CLI 使用合成配置；没有远程 CI 或真实设备验证。

新增行为覆盖：错误行后仍查询有效行；默认 TCP/显式 UDP/空服务；同设备和跨
设备关联；新 revision/实时 reservation；过期或歧义拓扑；冷/热缓存及取消；
有效期边界与 DST；原生 VIP/ACL；端口别名与精确原始策略命中；双设备 NAT
时间关联；未知日历及动态池不产生确定绑定；有限期设计及外部时段保持。

缓存/发现修复另有修复前 overlay 的失败证据：两设备、重复两行的单批次在
`MaxSourceBytes=1` 与 `MaxEntries=1` 下分别发生 10 次、8 次 backing load，
修复后均为 2 次，manifest 仍只读取一次。无接口及部分接口缺失时保留已知/
未知的条件声明；显式 `real`/`translated` 的业务坐标、误用原始坐标及未知
映射也有对应回归。`go test -race -count=1 ./inventory ./operations`、
两个包的 `go vet` 及补充的部分接口专项 race 均通过；本次未重跑性能基准。
无 zone 表、原生 zone 引用缺失及部分 zone 表三例也有修复前失败回归，
有效结果始终保留未知，声明几何的已知性仍由原生引用证据决定。

迁移新增独立有限元组枚举、组合偏移/常量、混合选中归属和目标外保持回归。
Huawei 到 Huawei 的 DNAT 端口迁移通过原生生成及独立回读；扩大到未选择源地址被拒绝。

合成性能数据来自 Go 1.27.1 / macOS arm64 / Apple M5，10 次样本、每次 100ms。
缓存 fixture 含 1000 个地址；索引 fixture 含 10k 单主机和覆盖它们的广网段。

## 后续完善方向

1. **SRX DNAT 端口迁移**：原像与别名查询已有证明，但完整迁移仍被既有原生
   等价性检查拒绝。下一步应隔离生成前后的真实差异，补相应原生回读证据，
   通过后再扩充 capability；不应放宽验证阈值绕过拒绝。
2. **归属及入口资料**：接入管理员维护的 revision 绑定 protection/ingress
   资料和可信设备时钟。普通用户无需填写 zone/VRF，但算法不能从地址对象、
   默认路由或反向路由中创造这些证据。
3. **动态 NAT 会话命中**：查询真实分配需增加独立的、带设备/revision/时段
   约束的会话证据。配置池只提供可能范围，不能代替当前会话表。
4. **端到端性能**：下一阶段使用脱敏拓扑、声明数量、NAT 密度和查询分布测量
   冷启动、缓存淘汰、热查询及峰值并发，再决定是否增加面向多设备的共享索引。
   当前局部基准不足以支持额外后台线程、数据库查询缓存或无界全量预热。
5. **设备接受性**：保留七厂商各自的语义能力矩阵，依次增加已确认版本的原生
   输入/输出夹具。真实设备、远程 CI、提交和发布应分别记录验证证据。
