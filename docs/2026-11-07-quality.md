# Firemon 模块质量整改

本轮基于已有开发改动继续整改，未提交、推送或发布。七个厂商范围、快照格式、
策略与 NAT 领域对象保持一致。修改按已有组件职责展开，未增加通用管理框架。

## 迁移计划的所有权

迁移原先直接调用 `RenderNative`，绕过其他计划入口使用的复制和取消边界。
回归已复现：渲染器保留参数或命令切片后可以改写计划；渲染中取消后仍可能成功；
typed-nil 原生渲染器会 panic。NAT 编译器返回的声明也存在共享切片。

迁移现在统一经过 `renderNative`。编译器结果先检查新增声明和 Change 内部成员的
预算，再深拷贝；回调返回后先检查取消。渲染器只接收独立参数，返回命令也被复制。
NAT 与仅包含 Schedule 的迁移都覆盖了保留切片、取消及 typed-nil 回归。

## 查询和图构建预算

用户确认 `MaxRegions` 同时约束输入和结果，默认仍为 4096。策略、NAT、数据包、
静态别名查询在未知或无匹配捷径之前预检；`Match` 检查实际 input，路由查询检查
规范化地址区间数。取消、无效参数的优先级保持不变；输入超限返回 `policy.ErrBudget`，
没有部分结果。未扩大 MaxCombinations 的含义或增加新的笛卡尔积计费。

整图导出前使用已缓存的 `DeclarationSize()`，覆盖候选构建、迁移读回、策略等价、
NAT 证明、版本比较、收敛和回收。仅枚举顶层记录时继续使用 `RecordCount()`。
无 NAT 且不需要复制图的提前成功路径保留。

单个对象拥有大量重复地址区间的测试，原先会在低预算拒绝前复制约 0.1–1.3 MB；
新实现先拒绝，沿用已有分配上限验证。原有低预算测试无需放大阈值。

## 地址区间与解析组件

`AddressSet` 负责有序区间不变量。差集和 IPv6 交集使用双游标扫描，包含判断直接
检查覆盖，不生成差集。IPv4 继续使用 `gatework/set`；保留闭区间端点、双栈分离、
IPv4-mapped IPv6 和不可变所有权。独立点集 oracle 现在覆盖多个离散区间。

删除 Huawei、Netscreen 中不使用接收者状态的两处 commit 转发方法，12 个调用点
直接使用事务 Emit/Commit。Builder 继续原子提交声明和来源证据，失败时一起回滚。
本轮未改变厂商声明语义、接口与路由绑定顺序或未知引用处理。

## JSON 输入和设备响应

`DecodeBatchRequest(ctx, reader)`、`DecodeTopology(ctx, reader)` 接收调用者上下文，
没有旧签名包装。共享 reader 在每次读取前检查取消，连续 100 次零进度后返回
`io.ErrNoProgress`。保留 limit+1 探测、原始读取错误优先和读取失败无部分数据；
借用 reader 的关闭与单次阻塞读取中断由所有者负责。

保存证明先移除确切的最终提示符和命令回显，再处理原始响应历史。按连接器已经
验证的 UTF-8/GBK/GB18030 编码解码并校验往返，避免终端重绘掩盖拒绝。已有
`x/text v0.43.0` 改为直接依赖，版本和 go.sum 未变。

Fortinet 使用配置词法器识别完整 system global 内唯一的 cfg-save automatic。
主机名、标题等配置值可以含 error/failed；范围外字段、嵌套或未闭合块、重复冲突、
manual/revert 以及被回车重绘隐藏的拒绝均失败，不生成成功持久化回执。
