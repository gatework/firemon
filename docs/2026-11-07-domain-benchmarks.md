目录现在会解析组的完整覆盖、规范化多段服务集合，并确认原生命名在请求作用域中仍指向同一对象。完整覆盖相等才可复用；更宽地址、带孔服务集合、外部作用域及被局部同名对象遮蔽的引用均不可复用。[对象目录测试](../plan/object_catalog_test.go) 验证这些差异及最终计划证明。基准中的简单单范围、单服务对象在两个版本都能复用，适合观察额外成本；它没有测量新支持的对象组所减少的对象数。组数量、嵌套深度、服务片段数和作用域数量都会增加 CPU 工作，不能从本表外推到大型生产配置。缓存仍消耗逻辑访问预算，命中缓存不会绕过资源限制。

预算审查还发现，旧解析路径在检查剩余预算前调用 `Record()`，会复制全部服务项或组成员。修复保留 `Record()` 的独立 DTO 语义，增加只读值迭代；地址范围先按 `RangeCount()` 预检，服务项和组成员逐项检查预算。[Resolver 测试](../policy/resolver_test.go) 对四类各 65,536 项的声明使用 1 步预算，要求 `ErrBudget`、没有部分数据，且解析阶段分配不超过 64 KiB；同一大型图中的小查询仍可成功。单独的 65,536 服务项复现中，调用分配从 1,310,768 B 降至 48 B；这是一次边界复现，不是上述六次基准的统计结果。

目录和解析器共享资源额度时，目录自身的工作也会消耗预算。目录现在在每次组或复杂服务解析前调用 `Resolver.RestrictVisits` 收紧剩余额度，再按实际访问差额扣账；该方法只能收紧上限，缓存不能绕过它。[共享预算回归](../plan/object_catalog_budget_test.go) 让直接地址索引先消耗额度，再遇到 32,768 项服务声明，验证剩余 0 或 1 步时立即停止、没有部分目录、分配不超过 64 KiB。移除收紧调用后，该回归复现了零剩余额度下约 6.55 MB 的分配；恢复后通过。

验证范围为本地合成测试和 `go vet`，覆盖根包以及 `policy`、`plan`、`operations`、`analysis`、`vendors`。本记录不提供 CI、生产负载或真实设备验证证据。
